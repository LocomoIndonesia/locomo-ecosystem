# Locomo Agent OS Auto-Boot Rules

Setiap kali sesi obrolan baru (chat session) dimulai di dalam workspace ini, Agen AI (termasuk Antigravity) WAJIB secara proaktif melakukan langkah-langkah onboarding berikut sebelum menanggapi atau mengeksekusi instruksi pengguna:

## 1. Menjalankan Protokol Onboarding ("jalankan locomo.agent")
Agen harus langsung menganggap perintah "jalankan locomo.agent" telah dipicu secara otomatis.
- **Langkah 1**: Baca status kognitif aktif dari berkas memori Trinity:
  - `.locomo.agent/id.json` (Trinity 1 - Guardrails & Tech Stack)
  - `.locomo.agent/cortex/cortex-core.json` (Trinity 2 - Status & Fase Aktif)
  - `.locomo.agent/docs/project-context.json` (Cartridge - Project Context)
- **Langkah 2**: Lakukan pelaporan boot sequence ke obrolan dengan format terstruktur:
  - **Locomo Agent OS Active Mode**: `[OS_MODE: COGNITIVE]` atau `[OS_MODE: DRIVERLESS]` (lakukan cek cepat status driver `docker ps` jika `env_status` bukan `running`)
  - **Environment Status**: `idle` / `running` / `error` (sesuai status aktif)
  - **Active Project**: (diambil dari `project-context.json`)
  - **Current Phase**: (diambil dari `cortex-core.json`)
  - **Priorities**: (prioritas aktif dari `cortex-core.json`)

## 2. Context Lock & Progressive Disclosure
Setelah pelaporan boot selesai, patuhi batasan context lock:
- Jangan melakukan pemindaian Docker berulang kali dalam sesi yang sama.
- Gunakan pendekatan *Lazy Loading* (menggunakan pencarian grep/file parsial) untuk membaca `docs/domain-knowledge.json` atau file besar lainnya guna menghemat token.

## 3. Aturan Respon Sederhana & Dokumentasi Mandiri
- Respon chat langsung wajib dibuat sederhana, ringkas, dan to-the-point.
- Jika memerlukan laporan detail, panduan arsitektur, atau hasil analisis yang panjang, tulis dokumentasi tersebut ke dalam berkas Markdown (`.md`) di folder `.docs/` (satu project) atau `<nama-project>/.docs/` (multi-project), atau sebagai skrip temporary ke `.locomo.agent/scratch/`; kemudian cantumkan tautan berkasnya saja di chat.

## 4. Aturan Eksekusi Perintah (Docker-Only Execution)
- Semua perintah skrip (seperti `python`, `php`, `composer`, `npm`, `node`, dll.) **TIDAK BOLEH** dijalankan langsung di host (Windows/Linux).
- Semua eksekusi wajib dijalankan di dalam kontainer Docker yang sesuai (menggunakan `docker compose exec` atau `docker compose exec semantic-api python3` untuk skrip Python).
- Semua perintah toolchain HANYA dari registry kanonis `skills/roms/environment.md`. Dilarang trial-and-error merangkai perintah di terminal.

## 5. Signature File Wajib
- Setiap file yang dibuat/dimodifikasi agen wajib header baris pertama: `File generated by <Tool>, and Orchestrated by Ronald Poetra (Zaid) last updated at <timestamp ISO>` (bungkus komentar sesuai bahasa). Format lama tidak berlaku.
